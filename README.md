# astrbot_plugin_bili_dynamic

B 站 UP 主动态订阅推送插件（AstrBot），使用 **QQ 官方机器人原生 Markdown** 排版，
按会话（群聊 / 私聊）独立订阅并推送。

## 功能特性

- **全局监控**：所有被任意会话订阅的 UP 主统一去重轮询，多个群订阅同一 UP 主
  只会请求一次 B 站接口，水位线（已处理到的最新动态 id）全局共享；
- **按会话推送**：每个会话通过指令独立维护订阅列表，动态只推送给订阅了对应
  UP 主的会话；
- **Markdown 卡片排版**：图文 / 视频投稿 / 转发 / 专栏 / 文字动态各有模板，
  多图排成一行表格（表格内动图自动转为查看链接），图片使用 B 站图床原图
  链接；订阅 / 取消订阅均返回 UP 主信息卡片；
- **可点击交互标签**：订阅列表自带「取消订阅」按钮、帮助消息的指令均为
  QQ 原生可点击标签（`qqbot-cmd-input`），点击自动把指令填入输入框；
- **置顶动态特殊处理**：置顶旧动态不会被当作新动态重复推送；订阅时不推送任何
  历史动态（包括当时的置顶动态）；「新发布并被置顶」的动态正常推送并带有
  （置顶）标记；
- **接口自动降级**：完整动态接口被风控（偶发返回空数据 / 错误页）时自动降级到
  匿名更稳定的图文 opus 接口，保证基本可用。

## 安装

1. 将本目录放入 AstrBot 的 `data/plugins/` 目录（或通过插件市场安装），
   目录名为 `astrbot_plugin_bili_dynamic`；
2. 重启 AstrBot 或在 WebUI 插件管理中重载插件；
3. 依赖 `aiohttp`（AstrBot 自带，一般无需额外安装）。

建议在插件配置中填写 **SESSDATA**（可选）：匿名状态下 B 站完整动态接口存在
概率性风控（同一 UP 主时好时坏），填写后可显著提升稳定性；不填写也能用，
但可能只推送图文动态（自动降级，见下文「工作原理」）。

## 指令

| 指令 | 说明 |
| --- | --- |
| `/bili 订阅 <UID>` | 订阅一个 UP 主（返回 UP 主信息卡片） |
| `/bili 取消订阅 <UID>` | 取消订阅（返回取消成功卡片） |
| `/bili 订阅列表` | 查看本会话订阅的所有 UP 主（名字/UID/取消按钮 三排表格） |
| `/bili 测试` | 立即触发一次全局检查（60 秒冷却） |
| `/bili 状态` | 查看插件运行状态 |
| `/bili 帮助` | 显示帮助（每条指令均为可点击标签） |
| `/bili`（不带子指令） | 显示帮助（与 /bili 帮助 相同） |

> 指令均支持别名：订阅（关注/subscribe）、取消订阅（取关/unsubscribe）、
> 订阅列表（列表/list）、测试（检查/刷新/check）、状态（status）、帮助（help）。
> 订阅列表 / 帮助中的按钮为可点击标签，点击会自动把指令填入输入框。

## 配置项

| 配置 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `sessdata` | string | 空 | B 站 SESSDATA，填写后接口更稳定 |
| `poll_interval` | int | 120 | 轮询间隔（秒），建议 60~300 |
| `max_push_per_poll` | int | 5 | 单次每个 UP 最多推送条数（防刷屏） |
| `push_pinned` | bool | true | 是否推送置顶动态（关闭则一律不推） |
| `block_vote_join` | bool | true | 屏蔽「参与了投票」动态（全局开关，只影响参与投票方的自动动态） |
| `admin_only` | bool | false | 是否仅管理员可管理订阅 |

## QQ 官方机器人注意事项

1. **原生 Markdown**：自 2026-04-23 起，群聊 / 单聊场景的自定义 Markdown 消息
   已对所有机器人开放，无需单独申请模板。若机器人意外无法发送 Markdown，
   AstrBot 会自动回退为纯文本发送（排版会退化为原始文本）；
2. **主动消息**：动态推送属于机器人主动消息，需要机器人在 QQ 开放平台侧具备
   主动消息能力，否则推送可能无法送达（这与插件无关，取决于机器人账号）；
3. **图片转存**：Markdown 内的图片由 QQ 服务端下载转存，插件直接使用 B 站
   图床原图链接（不做缩略，保证清晰度），图片体积可能较大、转存稍慢；
   B 站图床偶发概率性 403（边缘节点行为），个别图片可能显示失败，属正常现象；
4. 群聊中机器人回复、推送均可能受 QQ 平台频率限制，插件已内置请求间隔与
   推送节流；
5. **交互标签**：订阅列表 / 帮助中的按钮为 QQ 原生「参数指令」组件，
   点击自动将指令填入输入框；个别客户端版本若不支持会显示为普通文本，
   此时手动输入指令即可。

## 工作原理

- **水位线判断新动态**：每条动态的 `id` 全局单调递增，插件为每个 UP 主记录
  `latest_id`（水位线），只推送 `id > latest_id` 的动态并取 `max(id)` 推进。
  置顶旧动态虽然排在列表最前，但其 id 小于水位线，因此不会被误判为
  「有新动态」；订阅 / 重新激活监控时先建立基线，不推送历史动态；
- **接口链路**：`feed/space`（完整，含全部类型）→ 失败或空数据时重试 →
  仍失败则降级 `opus/feed/space`（图文，字段较少：无发布时间、仅一张封面图、
  作者信息由订阅时缓存补齐）；
- **推送节流**：多会话 / 多动态推送之间自动间隔，单 UP 单轮推送条数上限可配。

## 已知限制

- 无 SESSDATA 时完整接口可能持续返回空（风控），此时只能推送图文动态；
- 降级模式（opus 接口）的推送缺少发布时间，且只显示一张封面图；
- 极端的超长图（如招聘长图）在卡片内会显示为窄长条；
- 插件长时间离线后恢复时，单个 UP 主积压的动态只推送最新的
  `max_push_per_poll` 条。
